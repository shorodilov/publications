# Code of Conduct

## Purpose

This repository exists to develop, review, and maintain publication
materials in a calm, practical, and engineering-oriented environment.
The goal is to make collaboration predictable, respectful, and useful.

Everyone who participates in this repository is expected to help keep the
space focused on the work: documents, schemas, examples, issues, review,
and improvements.

## Expected behavior

Participants are expected to:

- Treat other people with respect, even when disagreeing strongly.
- Keep criticism focused on ideas, text, code, structure, or decisions.
- Explain concerns clearly and, when possible, propose a concrete change.
- Assume that maintainers and contributors may have limited time.
- Respect repository scope and avoid derailing issues or pull requests.
- Accept maintainer decisions when a discussion has been closed.

Good-faith disagreement is welcome. Personal attacks are not.

## Unacceptable behavior

The following behavior is not acceptable:

- Harassment, insults, threats, intimidation, or sustained personal
  attacks.
- Discriminatory or dehumanizing language.
- Sexualized comments, imagery, or attention in project spaces.
- Publishing private information without explicit permission.
- Repeated off-topic comments after being asked to stop.
- Spam, trolling, sealioning, or attempts to exhaust maintainers through
  bad-faith argument.
- Using issues or pull requests to pressure maintainers into unrelated
  support, promotion, or debate.

## Scope

This Code of Conduct applies to all project spaces, including issues,
pull requests, discussions, reviews, commit messages, and any other
repository-managed communication channel.

It also applies when someone represents the project in a public space.

## Enforcement

Maintainers may take any action they consider appropriate, including:

- Editing or deleting comments.
- Asking a participant to stop a behavior.
- Closing or locking an issue or pull request.
- Limiting participation in a discussion.
- Blocking a participant from the repository or organization.

Maintainers should prefer the smallest effective action, but they are not
required to tolerate behavior that damages the project space.

## Reporting

If you see behavior that violates this Code of Conduct, report it to the
maintainers through a private channel when one is available.

If no private channel is available, open a minimal public issue that does
not include private details and ask the maintainers to provide a private
contact path.

Reports should include:

- A link to the relevant issue, pull request, comment, or discussion.
- A short description of what happened.
- Any context that helps maintainers understand the situation.

Maintainers should handle reports with care and avoid exposing private
information unnecessarily.
